# 内容工作台 · 功能规划

> 2026-09-14 Park 出门前给的方向：工作台覆盖「获取 → 处理 → 加工 → 录制 → 发布 → 数据监控」全流程，口播 workflow 嵌进来。确定性高的先做。

## 一条主线

```
Obsidian Clipper 剪藏 / 原始输出 / 日报
      │
      ▼
① 每日统筹 ──── 今天读什么 · 哪几条能拍成视频（首选 + 备选 + 口播骨架）
      │
      ▼
② 选题 ──┬── 文章线：卡兹克写作 → 编辑 → 研习室            （P1 已完成）
         │
         └── 视频线：拍摄提纲 → 录制 → 口播 workflow 14 步 → 成片
                                          │
                                          ▼
③ 发出 ──── 各平台文案包 · 发布记录（抖音 / 视频号 / 小红书 / X / B 站 / YouTube / 研习室）
      │
      ▼
④ 数据 ──── 发出后 24h / 72h / 7 天数据 · 自己的视频自动拆解 · 回流到下一次选题
```

## 里程碑

| # | 里程碑 | 做什么 | 确定性 | 状态 |
|---|---|---|---|---|

| P2-2 | 拍摄提纲 | 视频选题生成口播提纲：前 15 秒讲清主线、3–5 段论点与例子、结尾；可编辑 | 高 | 计划 |
| P2-3 | 视频项目进度 | 关联口播 workflow 项目目录，按 14 步完成证据读出当前阶段、审批门、产物；打开 worktable；给出继续命令 | 中高（只读） | 计划 |
| P2-4 | 发出记录与数据回收 | 选题关联已发抖音视频（自动匹配 + 手动选），显示发出后数据变化，满 48 小时建议拆解自己的视频 | 高 | 计划 |

## 边界（不变）

- 不代 Park 在任何平台正式发布；发布动作永远需要 Park 本人。
- 抓取遇风控立即停止；抖音站内搜索不做。
- 口播 workflow 的三个人工审批门（Hook、视觉规格、终审）留给 Park，工作台只显示和提醒。
