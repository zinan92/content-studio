## 1. 要做成什么

Park 做 AI 主题抖音长视频（10–40 分钟），未来扩展小红书、X、视频号。拆解台帮他回答一个问题：**一条视频为什么爆 / 为什么不爆**。

- 监控三类内容：自己的视频、对标账号的视频、手动贴的链接。
- 爆款判定：点赞 ÷ **该账号自己的**点赞中位数（10 万粉的号平时 5000 赞，突然 20 万赞，就是 40 倍样本）。
- 拆解的主材料是**语音转成的文字**；截图、节奏是辅助。
- 自己的视频额外看创作者后台数据：涨粉、5 秒完播、2 秒跳出、平均观看时长、主页访问。

## 3. 复用边界（先读这里，不要重造）

2026-09-13 实测结果：

| 仓库 | 结论 | 实测证据 |
| --- | --- | --- |
| `zinan92/content-downloader` | **唯一的下载入口**，但抖音适配**需先修** | 主分支运行抖音下载直接报 `ImportError: cannot import name '_sanitize_cookies' from ...douyin.cookie_manager`。抖音需要登录 cookies。 |
| `zinan92/content-extractor` | **唯一的转写入口**，直接复用 | 中文测试视频转写准确（置信度 0.94）。注意：不支持纯音频文件，只收视频；它自带的 LLM 摘要依赖本机 CLI Proxy 或 `ANTHROPIC_API_KEY`，拆解台不依赖这个摘要。 |
| `zinan92/content-intelligence` | **只作参考**，不作依赖 | 它的"爆款归因"是跨账号打分；拆解台的基准是"账号自身中位数"，逻辑不同。可借鉴其 ingest 适配器写法。 |
| `zinan92/content-workbench` | **只作参考**，不在其上扩建 | 它的产品是"跨平台搬运/分发"，拆解台是"监控 + 拆解"，是不同的应用。 |
| `douyin-downloader`、`douyin-downloader-1`、`MediaCrawler` | **不在范围内** | 不要选用，避免多条下载链路并存。 |

新增、以上仓库都没有的能力：
1. **创作者后台逐条数据抓取**（`creator.douyin.com` 数据中心 → 投稿列表）。后台**只保留 90 天**，晚一天抓就永久少一天，所以放在第一个里程碑。
2. **结构拆解**：把转写文字切成 钩子 / 论点 / 案例 / 跑题 / 收束 / 引导，标出偏离主线的段落。
3. **对标账号库**与每日跟踪。

## 4. 里程碑

### M1 · 拆解跑通 + 后台数据开始存档
**完成的证据：** 3 条样本各出一份拆解报告，Park 读完认为"说中了"；自己账号的后台数据已落库。

- **M1-1 修复 content-downloader 的抖音下载**（在 content-downloader 仓开 issue）
  - 验收：单条抖音视频链接可下载到标准目录；缺 cookies 时给出明确提示；原有测试全绿。
- **M1-2 创作者后台逐条数据抓取（手动触发）**
  - 字段：播放、完播率、5s 完播、封面点击率、2s 跳出、平均观看时长、点赞、分享、评论、收藏、主页访问、粉丝增量。
  - 验收：一条命令把 90 天内全部作品的上述字段存为带抓取时间的记录；重复运行不产生重复记录；与后台页面人工抽查 3 条一致。
- **M1-3 拆解流水线**：链接 → 下载（M1-1）→ 转写（content-extractor）→ 结构拆解 → 报告数据 + 可读报告
  - 验收：三条样本都能从链接一路出报告；报告含主线一句话、分段时间轴（含跑题标记）、逐段原文、"为什么爆 / 为什么散"；每个结论引用原文时间点。
  - 样本：千雪AI `7658238400629083402`（66 倍）、柱子哥 `7645203889066724646`（19 倍）、Park 自己的 `7683154176955731234`（《AI越强，你越是在瞎努力》）。
  - **闸门：Park 读完三份报告认可后，才进 M2。**

### M2 · 对标监控
**完成的证据：** 对标账号每日新作品自动入库，超过门槛的自动进拆解队列。

- 对标账号库：增、删、列；抖音主页链接可直接加入。
- 每个账号拉近期作品，算自身点赞中位数与每条倍数。
- 每日定时抓取属于"产品运行所需的调度"，必须有独立说明、健康记录和停止开关。

### M3 · 前端接真实数据
**完成的证据：** 本机打开拆解台，四个页面全部显示真实数据，交互与样稿一致。

- 按样稿实现：我的视频、对标雷达、拆解队列、拆解报告。
- **必做：在前端页面粘贴主页链接即可加入对标账号**（识别抖音 / 小红书 / X / 视频号），不需要去后台操作。
- 视觉以样稿为准，不重新设计。

### M4 · 扩平台
小红书、X、视频号各自先调研采集方式，再单独立项。M4 之前，这三个平台的账号只入库、标"抓取待接入"。
